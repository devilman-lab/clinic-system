# 手術予約・手術枠管理システム（デモ）

外科手術を多く行うクリニック向けの、手術予約と手術枠管理のデモアプリケーションです。

紙のノートでの手術枠管理と、外部予約システムへの二重入力によって起きている
記入漏れ・調整時間の長さを解消することを目的としています。

---

## 1. このデモで証明したいこと

このデモの中心は、カレンダー表示ではなく **予約可能判定エンジン** です。

```
患者が希望する手術
  → その手術を実施できる医師
    → その医師の定例枠（曜日・時間帯）
      → 使用できる手術室
        → 手術に必要な予約枠の長さ
          → 既存予約との重複
            → 最短で予約できる日時
```

この一連の判定を自動で行い、次の 2 つの質問に即答できることを示します。

| ケース | 例 |
| --- | --- |
| ケース1 | 「A医師でC手術ができる日時はいつか」 |
| ケース2 | 「A・B・C医師の誰でもよいので、C手術を最短で予約できるのはいつか」 |

見た目だけのダミー検索ではありません。予約を1件入れると、同じ条件で再検索したときに
その枠が候補から消えます。`npm run verify` でこの挙動を実データに対して検証できます。

## 2. 実装した業務ルール

### 医師と対応可能な手術

医師ごとに実施できる手術が異なります（初期データ）。

| 医師 | 対応可能な手術 |
| --- | --- |
| A医師 | A〜H（すべて） |
| B医師 | A・B・C・D・E・F |
| C医師 | A・B・C・D・E |
| D医師 | A・B |
| E医師 | A・B・C・F・G |

### 手術時間と予約枠

「執刀時間」と「実際に確保する予約枠」を分けて管理します。
予約枠には前後の入れ替え・器材準備の時間が含まれます。最低予約単位は 30 分です。

| 手術 | 執刀時間 | 予約枠 |
| --- | --- | --- |
| A手術 | 15分 | 30分 |
| B手術 | 30分 | 30分 |
| C手術 | 45分 | 60分 |
| D〜G手術 | 60分 | 60分 |
| H手術 | 90分 | 90分 |

この対応関係は管理画面から変更できます（ハードコードしていません）。

### 手術枠（医師 × 手術室 × 曜日 × 時間帯）

定例枠は 4 つの軸で定義します。たとえば月曜日は次のようになっています。

```
月曜 午前  手術室1   09:30-11:00  A医師
                    11:00-12:30  B医師

月曜 午後  手術室1   13:30-15:00  A医師
                    15:00-17:00  C医師
          手術室2   13:30-15:30  B医師      ← 午後は2列稼働
                    15:30-17:00  E医師
```

### 第2・第4金曜日の追加枠

定例枠には「第N週のみ有効」を設定できます。
第2金曜・第4金曜は手術室2を終日開放し、手術室1に延長枠（16:00-18:00）を追加しています。

### 特定日の例外

特定の日付だけのルールを、通常の定例枠とは別に管理します。

- `BLOCK` … その日の枠を閉じる（例：院内研修のため午後休診）
- `ADD` … その日だけ臨時枠を追加する（例：繁忙期対応）

例外は定例枠より優先されます。

## 3. 予約可能判定ロジック

`findAvailableSlots()` は次をすべて満たす候補だけを返します。

1. 医師がその手術に対応できるか
2. 医師がその日・その時間帯に手術枠を持っているか（第N週指定も考慮）
3. その手術室が利用可能か
4. 必要な予約枠の長さを連続して確保できるか
5. 既存予約と重複していないか
6. 定例枠の範囲内に収まっているか
7. 例外日ルールがあればそれを優先しているか
8. 医師・手術室が同時に二重使用されていないか

**8 が単純な空き時間判定との決定的な違いです。**
同じ医師の予約は手術室が違っても枠を塞ぎ（医師は分身できない）、
同じ手術室の予約は医師が違っても枠を塞ぎます（部屋は共有できない）。

### 候補が見つからないときの理由表示

「見つかりませんでした」で終わらせず、理由を切り分けて返します。

| コード | 表示される内容 |
| --- | --- |
| `NO_CAPABLE_DOCTOR` | その手術を実施できる医師が登録されていない |
| `NO_DOCTOR_IN_FILTER` | 指定した医師はその手術に対応していない（対応できる医師名を併記） |
| `NO_SCHEDULE_IN_PERIOD` | 対応はできるが、指定期間内に手術枠がない |
| `NO_CONTINUOUS_BLOCK` | 枠はあるが必要な長さの連続した空きがない（期間内の最長の空きを併記） |
| `FULLY_BOOKED` | 期間内の枠がすべて予約で埋まっている |

### 設計方針

判定ロジックは UI からも DB からも切り離してあります。

- `src/lib/availability/engine.ts` … **DB に触らない純粋関数**。スナップショットを受け取って候補を返す
- `src/lib/availability/index.ts` … 必要なデータを一度にまとめて読み込み、エンジンに渡す

この分離により、判定ロジックだけを単体で検証でき、
日付 × 医師 × 手術室ごとに DB へ問い合わせる N+1 も避けています。

## 4. 機能一覧

### 院内スタッフ向け

- **ダッシュボード** … 本日の手術件数、次の手術、手術室ごとの稼働率、空き枠、未確定予約。
  土日など手術枠のない日に開いた場合は、次に手術枠がある日の状況を表示します
- **手術スケジュール** … 日／週／月表示。横軸が時間、縦軸が手術室または医師。
  定例枠・例外枠・予約済み・空き枠を色分けして重ね、空き枠はタップでそのまま予約へ
- **空き枠検索** … 手術・医師・期間・手術室を指定して検索。最短予約可能枠を最上部に大きく表示
- **予約管理** … 期間・担当医・ステータス・患者IDで絞り込み、詳細から変更・キャンセル
- **予約の変更／キャンセル** … 変更時も登録時と同じ重複チェックを通す

### 管理者向け（院内スタッフ自身で設定変更できる範囲）

- 医師管理（対応可能な手術の変更を含む）
- 手術管理（執刀時間・予約枠時間）
- 手術室管理
- 定例枠設定（曜日・時間・医師・手術室・第N週指定）
- 例外日設定（臨時枠の追加／枠を閉じる）
- システム設定

### 患者向け

- **公開予約表** … ログイン不要。日付・時間・手術の種類・空き状況のみを表示

## 9. ローカル起動方法

PostgreSQL の接続文字列が必要です（Neon の無料枠で十分です。Vercel 連携で作った DB をそのまま使えます）。

```bash
npm install          # postinstall で prisma generate が走ります
cp .env.example .env # DATABASE_URL を実際の接続文字列に書き換える
npm run db:push      # スキーマを DB に反映
npm run db:seed      # デモデータを投入
npm run dev          # http://localhost:3000
```

### 確認用コマンド

```bash
npm run verify     # 判定エンジンを実データで検証（検索→予約→再検索で枠が消えるか等）
npm run smoke      # 主要画面の疎通と権限分離を確認（サーバー起動中に実行）
npm run e2e        # Playwright で主要フローを検証（Desktop Chrome と iPad Safari）
npm run typecheck  # 型チェック
npm run lint       # ESLint
npm run build      # 本番ビルド
```

`npm run e2e` は初回のみブラウザの取得が必要です。

```bash
npx playwright install chromium webkit
```

検証している内容:

- C手術を A・B・C医師で横断検索 → 最短枠を予約 → 同条件で再検索するとその枠が消える
- 手術枠のない時刻へ予約を変更しようとすると理由付きで拒否される
- 対応できない医師は検索条件として選べない
- 公開予約表に患者名・患者IDが出ていない
- スタッフ権限では管理画面に入れない

## 10. 環境変数

| --- | --- | --- |

## 12. Vercel へのデプロイ

データベースは PostgreSQL を使います（Vercel のファイルシステムは実行ごとに破棄されるため、
SQLite では予約が保存されません）。ここでは Vercel Marketplace の **Neon** 連携を使う手順を示します。
追加のアカウント登録なしで、接続文字列が環境変数に自動設定されます。

### 1. Vercel にプロジェクトを作る

1. https://vercel.com/new を開き、GitHub のリポジトリを **Import**
2. Framework Preset は自動で **Next.js** になる。Build Command / Output は変更不要
   （`npm run build` = `prisma generate && next build` が使われる）
3. **まだ Deploy を押さない**。先に環境変数を設定する

### 2. Neon（PostgreSQL）を接続する

1. 同じ画面の左メニュー、または後で Project → **Storage** タブ → **Create Database**
2. **Neon** を選び、リージョンは **Asia Pacific (Tokyo)** を選択して作成
3. 作成後「Connect Project」でこのプロジェクトに接続する。
   これで `DATABASE_URL`（プール接続）と `DATABASE_URL_UNPOOLED`（直接接続）が
   環境変数に自動追加される

### 3. 残りの環境変数を設定する

Project → **Settings** → **Environment Variables** に以下を追加（Production / Preview 両方）。

| 変数名 | 値 |
| --- | --- |
| `SESSION_SECRET` | `openssl rand -base64 32` などで作った 32 文字以上のランダム文字列 |
| `TZ` | `Asia/Tokyo` |

`TZ` は必須です。「本日」「第N週」「曜日」の判定はサーバーのローカル時刻で行うため、
Vercel 既定の UTC のままだと、日本時間の朝 9 時まで前日の予定が表示されます。

### 4. スキーマとデモデータを本番 DB に入れる

ローカルの PC から本番 DB に対して実行します（`db:push` / `db:seed` は Vercel 上では動かしません）。

1. Vercel の Storage → Neon → **.env.local** タブから `DATABASE_URL_UNPOOLED` の値をコピー
2. ローカルの `.env` の `DATABASE_URL` をその値に置き換える（`TZ="Asia/Tokyo"` も残す）
3. 実行

   ```bash
   npm run db:push
   npm run db:seed
   ```

   `db:seed` は実行した PC の「今日」を基準に前後 4 週間分の予約を作ります。
   デモの直前に再実行すると、常に「今週」に予約が入った状態にできます。

### 5. デプロイ

1. Vercel の画面に戻り **Deploy**（すでに作成済みなら Deployments → **Redeploy**）
2. 発行された URL を開き、`admin` / `admin123` でサインイン
3. ダッシュボードに件数が出ていれば完了

### 6. 動作確認のポイント

- 空き枠検索 → 予約 → 同条件で再検索して、その枠が消えること
- 別のブラウザ／iPad で開いて、さきほどの予約がカレンダーに出ること（＝DB に保存されている）
- `/schedule` を未ログインで開き、患者名が出ないこと

### つまずきやすい点

| 症状 | 原因と対処 |
| --- | --- |
| ダッシュボードが「昨日」を表示する | `TZ=Asia/Tokyo` が未設定。追加して Redeploy |
| 予約しても再読み込みで消える | `DATABASE_URL` が SQLite のまま。Neon の値になっているか確認 |
| ビルドで `Prisma Client` の型エラー | `postinstall` の `prisma generate` が走っていない。Vercel の Install Command が `npm install` になっているか確認 |
| `db:push` が pgbouncer のエラーで止まる | プール接続を使っている。`DATABASE_URL_UNPOOLED` の値を使う |
| ログイン後すぐログイン画面に戻る | `SESSION_SECRET` 未設定。追加して Redeploy |

### ローカル開発について

`prisma/schema.prisma` は PostgreSQL 前提になっています。ローカルでも Neon の接続文字列を
`.env` に入れて動かすのが最も簡単です（本番と別の DB にしたい場合は Neon で **Branch** を切る）。

## 13. 外部予約システム（GMO 等）との連携について

**本デモでは GMO との連携部分はモック化しています。** 実際の API 通信は行いません。

将来差し替えられるよう、予約の登録・変更・取消は
`ExternalBookingProvider`（`src/lib/external/booking-provider.ts`）越しに呼び出しています。

```ts
export interface ExternalBookingProvider {
  readonly name: string;
  create(payload: ExternalBookingPayload): Promise<ExternalBookingResult>;
  update(payload: ExternalBookingPayload): Promise<ExternalBookingResult>;
  cancel(bookingId: string): Promise<ExternalBookingResult>;
}
```

本番では GMO 向けの実装クラスを用意し、`setBookingProvider()` で差し替えるだけで連携できます。
予約処理本体を書き換える必要はありません。

## 14. セキュリティ（デモ時点で実装済みの内容）

- **認証** … ログイン必須。セッションは HMAC-SHA256 署名付きトークンで改ざんを検出
- **Cookie** … `httpOnly` / `sameSite=lax` / 本番は `secure`。
  認証情報を `localStorage` に保存しないため、XSS でトークンを持ち出されません
- **CSRF** … 更新系はすべて Server Actions 経由（Next.js 側の Origin 検証が働きます）。
  加えて `sameSite=lax` を併用
- **権限チェックの二重化** … 画面側の出し分けだけに頼らず、
  すべての Server Action 内で `requireRole()` を実行
- **SQL インジェクション** … Prisma の型付きクエリのみを使用。文字列連結による SQL を書いていません
- **XSS** … React の既定のエスケープに従い、`dangerouslySetInnerHTML` を使用していません
- **入力値検証** … すべての Server Action の入口で zod による検証
- **値の改ざん対策** … 予約枠の終了時刻は画面からの入力を信用せず、
  手術種類の設定値からサーバー側で再計算
- **個人情報の分離** … 公開予約表には患者名・患者ID・生年月日・院内メモを一切渡していません
- **ログイン時の情報漏えい防止** … ユーザーの存在有無で応答時間が変わらないようにし、
  エラーメッセージも「ユーザーIDまたはパスワードが正しくありません」に統一
- **オープンリダイレクト対策** … ログイン後の遷移先は自サイト内の相対パスのみ許可
- **デモデータ** … 実在の患者情報は使用していません（すべて架空データ）

## 15. 本番運用時に追加で必要となる対策

医療情報を扱うシステムとして、本番稼働前に以下の整備が必要です。

### アクセス制御・認証

- 多要素認証、パスワードポリシー、アカウントロック、定期的な棚卸し
- 端末・IP による接続制限、セッションタイムアウトの短縮
- 役職・診療科単位の、より細かい権限設計

### ログと監査

- 認証ログ（成功・失敗）、操作ログ（誰がどの予約をいつ変更したか）の保全
- 患者情報へのアクセスログの取得と、改ざん困難な保管
- 「医療情報システムの安全管理に関するガイドライン」に沿った監査対応

### データ保護

- 保存時の暗号化、通信経路の TLS 強制（HSTS）
- 定期バックアップとリストア手順の検証、世代管理
- 個人情報の保持期間・廃棄手順の策定

- 障害時の縮退運用（紙運用への切り戻し手順を含む）
- 個人情報保護法・各種ガイドラインに沿った運用規程と職員教育

## 17. iPad での利用について

院内スタッフが iPad で使うことを前提にしています。

- 押せる要素は最低 44px の高さを確保
- 入力欄のフォントサイズを 16px 以上にし、フォーカス時の自動ズームを抑止
- サイドバーは画面幅に応じて引き出し式に切り替え
- 情報量の多いカレンダー・一覧表は横スクロールさせ、見出し列は固定
- ページ全体の引っ張りスクロールを抑止
